# Трейдинг в общей базе: задание на разработку

Версия 1, 13.09.2026. Автор: Клод (агент «Трейдер»). Заказчик: Антон.

## 1. Зачем и где границы

В общем внутреннем приложении появляется контур личного трейдинга. Он живёт рядом с
аналитикой Битрикса, но **отдельной схемой `trading`**, потому что это другие деньги,
другой уровень риска и другой список тех, кто имеет право это видеть.

Контур закрывает четыре задачи:

1. Хранит котировки инструментов, которыми Антон реально торгует, с историей по дням
2. Хранит журнал сделок и движение денег, и по ним считает капитал, доходность и просадку
3. Хранит идеи сделок и их исход, чтобы через полгода было видно, какие решения работали
4. Отдаёт наружу два среза: полный для дашборда Антона и обезличенный для Клода

**Что контур НЕ делает:** не исполняет сделки, не хранит ключи и доступы к бирже,
не связан с данными Битрикса ни одной внешней ссылкой.

## 2. Схема базы

Postgres, схема `trading`. Денежные поля в рублях, `numeric`, никаких `float`.

```sql
create schema if not exists trading;

-- 2.1 Справочник инструментов -------------------------------------------------
create table trading.instrument (
  id            bigserial primary key,
  symbol        text not null unique,        -- BTC, ETH, AAPL, AAPLx, GOLD
  name          text not null,
  asset_class   text not null                -- crypto | wallet_token | equity | etf
                check (asset_class in ('crypto','wallet_token','equity','etf',
                                       'commodity','index','fx')),
  tier          text check (tier in ('core','liquid','spec','cash','avoid')),
  venue_ticker  text,                        -- как называется в Telegram Wallet
  source_cg     text,                        -- id на CoinGecko
  source_yahoo  text,                        -- тикер Yahoo Finance
  source_stooq  text,                        -- запасной источник
  earn_apy      numeric(6,2),                -- ставка площадки, % годовых
  is_active     boolean not null default true,
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now()
);
create index on trading.instrument (asset_class, tier) where is_active;

-- 2.2 Дневные цены ------------------------------------------------------------
create table trading.price_daily (
  instrument_id bigint not null references trading.instrument(id) on delete cascade,
  trade_date    date   not null,
  close_usd     numeric(20,8),
  close_rub     numeric(20,8),
  source        text   not null,             -- coingecko | yahoo:AAPL | stooq:aapl.us
  loaded_at     timestamptz not null default now(),
  primary key (instrument_id, trade_date)
);
create index on trading.price_daily (trade_date desc);

-- 2.3 Внутридневные срезы (пока не наполняем, задел на будущее) ---------------
create table trading.price_tick (
  instrument_id bigint not null references trading.instrument(id) on delete cascade,
  ts            timestamptz not null,
  price_usd     numeric(20,8),
  price_rub     numeric(20,8),
  source        text not null,
  primary key (instrument_id, ts)
);

-- 2.4 Курсы валют -------------------------------------------------------------
create table trading.fx_rate (
  pair      text not null,                   -- USDRUB
  rate_date date not null,
  rate      numeric(20,8) not null,
  source    text not null,                   -- cbr
  primary key (pair, rate_date)
);

-- 2.5 Счета и площадки --------------------------------------------------------
create table trading.account (
  id        bigserial primary key,
  code      text not null unique,            -- tg_wallet
  name      text not null,                   -- Telegram Wallet
  currency  char(3) not null default 'RUB',
  opened_at date,
  is_active boolean not null default true
);

-- 2.6 Движение денег ----------------------------------------------------------
create table trading.cash_flow (
  id         bigserial primary key,
  account_id bigint not null references trading.account(id),
  flow_date  date not null,
  kind       text not null check (kind in ('deposit','withdrawal')),
  amount_rub numeric(18,2) not null check (amount_rub > 0),
  note       text,
  created_at timestamptz not null default now()
);
create index on trading.cash_flow (account_id, flow_date);

-- 2.7 Идеи сделок (пишет Клод, решение принимает Антон) ----------------------
create table trading.idea (
  id            bigserial primary key,
  instrument_id bigint not null references trading.instrument(id),
  created_at    timestamptz not null default now(),
  author        text not null default 'claude',
  direction     text not null check (direction in ('long','short')),
  horizon       text check (horizon in ('intraday','swing','position')),
  thesis        text not null,               -- почему цена должна пойти туда, одна строка
  entry_rule    text not null,               -- уровень или условие входа
  entry_price   numeric(20,8),
  stop_price    numeric(20,8) not null,      -- без стопа идея не существует
  target1_price numeric(20,8),
  target2_price numeric(20,8),
  rr            numeric(6,2),                -- прибыль к риску, меньше 2 не заводим
  size_pct      numeric(6,2),                -- доля депозита
  invalidation  text not null,               -- что ломает идею
  status        text not null default 'new'
                check (status in ('new','taken','rejected','stopped','target','expired')),
  closed_at     timestamptz,
  outcome_pct   numeric(8,3),                -- результат в процентах депозита
  lesson        text                         -- вывод после закрытия
);
create index on trading.idea (status, created_at desc);

-- 2.8 Сделки ------------------------------------------------------------------
create table trading.trade (
  id            bigserial primary key,
  account_id    bigint not null references trading.account(id),
  instrument_id bigint not null references trading.instrument(id),
  executed_at   timestamptz not null,
  side          text not null check (side in ('buy','sell')),
  qty           numeric(28,10) not null check (qty > 0),
  price_rub     numeric(20,8) not null check (price_rub > 0),
  fee_rub       numeric(18,2) not null default 0,
  idea_id       bigint references trading.idea(id),
  note          text,
  created_at    timestamptz not null default now()
);
create index on trading.trade (account_id, executed_at);
create index on trading.trade (instrument_id, executed_at);

-- 2.9 Рамки риска -------------------------------------------------------------
create table trading.risk_limit (
  account_id         bigint primary key references trading.account(id),
  risk_per_trade_pct numeric(5,2) not null default 5,
  daily_loss_pct     numeric(5,2) not null default 5,
  max_open_risk_pct  numeric(5,2) not null default 20,
  updated_at         timestamptz not null default now()
);

-- 2.10 Сработавшие уровни -----------------------------------------------------
create table trading.alert (
  id            bigserial primary key,
  instrument_id bigint references trading.instrument(id),
  fired_at      timestamptz not null default now(),
  kind          text not null,               -- level_break | daily_loss | drawdown | idea_invalidated
  message       text not null,
  payload       jsonb,
  is_read       boolean not null default false
);
create index on trading.alert (is_read, fired_at desc);

-- 2.11 Кривая капитала (считается джобом, не руками) --------------------------
create table trading.portfolio_daily (
  account_id       bigint not null references trading.account(id),
  as_of            date not null,
  market_value_rub numeric(18,2) not null,
  cash_rub         numeric(18,2) not null,
  equity_rub       numeric(18,2) not null,   -- market_value + cash
  invested_rub     numeric(18,2) not null,   -- сумма пополнений минус выводы
  pnl_rub          numeric(18,2) not null,
  pnl_pct          numeric(8,3),
  drawdown_pct     numeric(8,3),             -- от максимума капитала
  positions        jsonb not null,           -- [{symbol, qty, avg, price, value, weight_pct, pnl_rub}]
  calculated_at    timestamptz not null default now(),
  primary key (account_id, as_of)
);
```

### Представления

```sql
-- последняя известная цена по каждому инструменту
create view trading.v_price_latest as
select distinct on (instrument_id)
       instrument_id, trade_date, close_usd, close_rub, source
from trading.price_daily
order by instrument_id, trade_date desc;

-- текущие позиции из журнала сделок, средняя цена по методу средневзвешенной
create view trading.v_position_now as
with moves as (
  select account_id, instrument_id,
         sum(case when side = 'buy' then qty else -qty end) as qty,
         sum(case when side = 'buy' then qty * price_rub else 0 end) as buy_cost,
         sum(case when side = 'buy' then qty else 0 end)             as buy_qty,
         sum(fee_rub) as fees
  from trading.trade
  group by account_id, instrument_id
)
select m.account_id, m.instrument_id, i.symbol, i.name, i.asset_class,
       m.qty,
       case when m.buy_qty > 0 then m.buy_cost / m.buy_qty end as avg_price_rub,
       m.fees,
       p.close_rub, p.trade_date as price_date
from moves m
join trading.instrument i on i.id = m.instrument_id
left join trading.v_price_latest p on p.instrument_id = m.instrument_id
where m.qty > 0.0000000001;
```

## 3. Наполнение

### 3.1 Загрузчик котировок

Готовый сборщик уже написан и работает: `collector/collect.py` из репозитория
`MakeBiz/trader-market`. Источники и их роли:

| Источник | Что берёт | Ключ |
|---|---|---|
| CoinGecko | крипта и токены Wallet (AAPLx, SPYx), цены в USD и RUB, история за год | не обязателен, но demo-ключ снимает лимиты |
| Yahoo Finance | акции США, фонды, золото, серебро, нефть, индексы, дневные свечи | не нужен |
| Stooq | запасной источник, если Yahoo молчит | не нужен |
| ЦБ РФ | официальный курс USD/RUB | не нужен |

**Что нужно от разработки:** добавить в сборщик режим записи в Postgres вместо файлов.
Это одна функция, интерфейс уже плоский: сборщик отдаёт строки
`symbol, asset_class, date, close_usd, close_rub, source`.

Запись строго идемпотентная:

```sql
insert into trading.price_daily (instrument_id, trade_date, close_usd, close_rub, source)
values (:id, :date, :usd, :rub, :source)
on conflict (instrument_id, trade_date)
do update set close_usd = excluded.close_usd,
              close_rub = excluded.close_rub,
              source    = excluded.source,
              loaded_at = now();
```

Перезапуск загрузчика за тот же день не должен ничего ломать и не должен плодить дубли.

### 3.2 Регулярные задачи

| Задача | Когда | Что делает |
|---|---|---|
| `collect_prices` | 03:30 и 15:30 по Дубаю | тянет котировки, пишет `price_daily` и `fx_rate` |
| `rebuild_portfolio` | сразу после сбора | пересчитывает `portfolio_daily` с даты первой сделки |
| `check_alerts` | после пересчёта | сверяет цены с уровнями активных идей, пишет в `alert` |
| `export_public` | после пересчёта | выкладывает публичные срезы (раздел 5) |

`rebuild_portfolio` считает так: на каждый день от первой сделки до сегодня разворачивает
журнал сделок на эту дату, оценивает позиции последней известной ценой **не позже этой даты**
(в будущее не заглядывать, иначе история будет врать), прибавляет свободные деньги и пишет строку.
Полный пересчёт за год это несколько тысяч строк, занимает секунды, поэтому пересчитываем
всегда целиком, а не инкрементом: так исправление задним числом само чинит всю кривую.

## 4. API приложения

Все ручки под общей авторизацией приложения, доступ только у Антона.

| Метод | Путь | Отдаёт |
|---|---|---|
| GET | `/api/trading/market/latest` | последние цены по всем активным инструментам плюс изменения за сутки, неделю, месяц |
| GET | `/api/trading/market/history?symbol=BTC&from=&to=` | дневной ряд по инструменту |
| GET | `/api/trading/portfolio/summary` | капитал, вложено, результат, доли, риск в рублях |
| GET | `/api/trading/portfolio/history?from=` | кривая капитала по дням |
| GET | `/api/trading/positions` | текущие позиции с P&L и весами |
| GET | `/api/trading/ideas?status=new` | активные идеи |
| POST | `/api/trading/trades` | внести сделку |
| POST | `/api/trading/cash-flows` | внести пополнение или вывод |
| PATCH | `/api/trading/ideas/{id}` | сменить статус идеи и записать исход |
| GET | `/api/trading/alerts?unread=1` | несработавшие уведомления |

Внесение сделки должно быть быстрым: одна форма, поля инструмент, направление, количество,
цена, комиссия, дата. Всё остальное считается само.

## 5. Как Клод читает данные (самое важное для нас)

Облачная среда Клода ходит в интернет через жёсткий белый список. Из всех хостов,
которые нужны для этой задачи, доступны только `raw.githubusercontent.com` и `api.github.com`.
Биржевые API, домен приложения и любые сторонние адреса недоступны. Это не настройка,
это ограничение среды.

Поэтому задача `export_public` раз в сутки (и по кнопке) кладёт в публичный репозиторий
`MakeBiz/trader-market` два файла:

**`data/latest.json`** — рыночный срез. Ничего личного, это просто котировки, они и так публичны.

**`data/portfolio_public.json`** — портфель **без рублей**:

```json
{
  "as_of": "2026-09-14",
  "positions": [
    {"symbol": "USDT", "weight_pct": 35.4, "pnl_pct": 0.3, "since": "2026-09-13"},
    {"symbol": "BTC",  "weight_pct": 32.4, "pnl_pct": -1.2, "since": "2026-09-13"}
  ],
  "equity_index": 98.8,        // капитал, где старт = 100
  "pnl_pct": -1.2,
  "drawdown_pct": -1.2,
  "cash_share_pct": 35.4,
  "risk": {"per_trade_pct": 5, "daily_loss_pct": 5}
}
```

Долей и процентов мне хватает для любых рекомендаций. Абсолютные суммы нужны только
для расчёта размера позиции в рублях, и их Антон называет в чате, когда они меняются.
Так в публичный доступ не уходит ни одна сумма, а автономность сохраняется.

Если позже появится желание отдавать мне полные данные, правильный способ это отдельный
read-only эндпоинт с токеном, но тогда сначала нужно проверить, что домен приложения
попадает в белый список среды. Пока считаем, что нет.

## 6. Чего делать нельзя

- **Не класть трейдинг в те же таблицы, что Битрикс.** Отдельная схема, отдельные права.
  Когда всё в одной куче, рано или поздно кто-то соединит выручку компании с личным портфелем
  и получит цифру, которой не существует
- **Не хранить в базе ключи, пароли и токены доступа к площадкам.** Контур только читает
  рынок и ведёт учёт, он ничего не исполняет
- **Не считать деньги в `float`.** Только `numeric`, иначе на тысячной сделке появится
  копеечная расходимость, и ты потратишь вечер на её поиск
- **Не оценивать позицию ценой из будущего.** При пересчёте истории брать последнюю цену
  не позже расчётной даты, иначе кривая капитала покажет доходность, которой не было
- **Не удалять строки из `price_daily`.** Ошибочные значения перезаписывать, а не стирать:
  так видно, что источник когда-то врал
